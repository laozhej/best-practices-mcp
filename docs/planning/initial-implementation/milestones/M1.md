# M1 — Foundations, catalog and QA tooling

## Commitments

M1 established all nine typed input/result contracts, strict JSON and alias normalization, an offline catalog for all six supported levels, SDK result adaptation, package foundations and a minimal HTML QA renderer. It also prepared the M0 baseline report from recorded evidence without presenting historical commands as freshly executed.

## Findings and fixes

Independent review corrected the distinction between unknown-tool protocol errors and structured domain errors, verified deterministic discovery and preserved the difference between the upstream major category and requirement strength. Catalog generation retained official wording, source provenance and required notices. Result schemas covered both success and error payloads.

The report renderer was corrected to preserve failed, missing and stale evidence rather than manufacture acceptance. It escaped displayed values, avoided running commands while rendering, and separated technical checks from review status. Packaging checks included the data and development inputs needed for qualification.

## Outcome and limits

The foundations and offline catalog gate passed after review. Public-read tools, document operations and storage were still later work at this checkpoint. The report mechanism supported human verification of the milestone without adding any MCP runtime feature. Detailed QA output is archived privately; the reusable tooling remains maintained.
