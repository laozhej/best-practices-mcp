# M5 — Compatibility and independent-host qualification

## Commitments

M5 established Python 3.11 as the supported minimum, native Python 3.11/3.12 checks on Linux, macOS and Windows, fresh wheel/sdist qualification, server line/branch coverage and an independent application-host check. Required evidence included executed installations and tool calls, not just committed workflow definitions.

## Findings and fixes

Cross-platform review corrected locale-dependent fixture/pipe handling to explicit UTF-8, rejected Windows read-only draft replacement before mutation, and covered managed directory reparse points with a native junction test. Coverage tooling was corrected to measure SDK-launched server processes without modifying production code or exposing general environment variables. Platform-specific instrumentation issues were resolved without suppressing strict startup diagnostics.

The actual desktop host exposed an older-protocol discovery failure. All success/error branches were already objects; explicitly declaring an object root preserved the accepted contract while satisfying the SDK's legacy schema requirement. Modern and legacy stdio regressions verified the correction, followed by actual desktop calls through all nine tools.

Catalog review found that upstream deliberately omits entailed requirement flags. The generated public booleans now expand `met_url_required ⇒ met_justification_required` and `na_justification_required ⇒ na_allowed`. Validation keeps the stronger URL finding without a redundant justification finding. Independent review confirmed unchanged acceptance behavior.

The testing policy was clarified: required conformance tests derive from documented procedures, criteria YAML/locale and agreed contracts. Ruby execution and comparisons against Ruby-generated fixtures moved to an explicit optional maintainer command, with no runtime or tool-scope change. Required native CI passed without Ruby.

## Outcome and limits

The six native combinations, fresh wheel/sdist checks and independent desktop qualification passed. Desktop checks covered errors, creation/read/rejected-patch preservation, explicit versus stored inputs, persistence through a fresh process, and byte-exact delivery of a large multi-entry URL and script. The large artifacts were not opened or executed, and their measured sizes do not establish universal host/browser capacity.

Coverage is a measured baseline rather than an arbitrary percentage gate. Reviewed corrections and subsequent required checks completed without remaining technical blockers. No website save or package publication was part of M5. Initial release preparation and actual public-index verification remain M6 activities.
