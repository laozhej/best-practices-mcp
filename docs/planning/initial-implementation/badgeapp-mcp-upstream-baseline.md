## Frozen endpoint and representation map

Use production origin `https://www.bestpractices.dev` with locale-independent JSON routes and English HTML edit URLs. GET only; no authentication, user cookies, arbitrary origins, or third-party fetches.

| Operation | Mapping |
| --- | --- |
| Numeric discovery/progress | `/projects/{project_id}.json`; numeric find uses page=1 only. A 404 is empty discovery or project_not_found for progress/generation. |
| Exact URL discovery | `/projects.json?url={query}&page={page}`; the provided URL is a query value, never fetched. Preserve upstream candidates. Classify an exactly comparable repo/homepage match when possible; otherwise use match_basis=url_query because upstream has its own URL normalization. Never discard candidates using the stricter artifact-identity comparison. |
| Text discovery | `/projects.json?q={query}&page={page}`; preserve upstream candidate order. |
| URL artifact | `/en/projects/{project_id}/{level}/edit` with the documented flat proposal parameters and `overrides` parameter, not Rails `project[...]` input names. Use deterministic parameter ordering and standard UTF-8 percent encoding; spaces encode as `%20`, never double-encode values. |
| Levels/sections | All six names map identically to upstream section names: passing, silver, gold, baseline-1, baseline-2, baseline-3. |
| Percentages | passing/silver/gold map to badge_percentage_0/1/2; baseline levels map to badge_percentage_baseline_1/2/3. Preserve upstream badge_level, tiered_percentage, baseline_tiered_percentage as separate summary metadata; never derive replacements. |
| Pagination | List JSON is an array. An empty page is complete; a nonempty page without authoritative next-page metadata has next_page=null and pagination_complete=false. A validated same-origin next link, if provided, supplies next_page; no total is inferred from length. Host may request page+1 explicitly when uncertain. Numeric results have pagination_complete=true. |

`find_project.query` is a string: trim ASCII surrounding whitespace; reject empty. An ASCII decimal positive integer string (leading zeroes accepted and normalized for lookup) is an ID; a string beginning with HTTP(S), case-insensitively, must parse as an absolute credential-free URL or fail invalid_query; everything else is textual search. `page` is a strict positive integer defaulting to 1. Numeric queries with other pages fail invalid_query. URL values preserve spelling after surrounding trimming; discovery does not rewrite them into guessed provider equivalents.

Generate canonical/display alias mappings from the pinned criteria definitions. Public JSON uses Baseline display aliases for both status and justification fields; normalize them on ingress and reject conflicting collisions. Serve official criterion text and inherited details using the pinned criteria model's rules; retain future/obsolete metadata in the generated catalog provenance rather than silently reclassifying requirements. Build the initial catalog reproducibly from the three input files above, with a development-only YAML parser pinned when introduced. Its generated JSON ships in the wheel and is read offline. No runtime YAML parser or refresh service is needed.

## Three important compatibility distinctions

1. The pinned proposal docs describe `?` resets, while controller `build_url_proposals` discards UNKNOWN. V1 deliberately omits `?` with an unsupported reason; it is never a reset request. An accompanying justification remains independently eligible. Only an explicit future scope decision may add resets.
2. The controller strips non-status URL values before comparing/applying them. Preserve raw draft and encoded text. Predict URL effects using Ruby String#strip parity (leading/trailing NUL, horizontal tab, LF, vertical tab, form feed, CR, and ASCII space), not Python's wider Unicode whitespace stripping. Script values preserve exact supplied strings. Include differences in transfer reason text where trimming changes a prediction. Criterion-credit justification checks retain their separate unstripped predicate.
3. Public JSON omits blank justifications. Progress answers must preserve that absence. For prediction only, a valid complete record using this pinned representation allows the adapter to treat an omitted known justification as blank. Missing statuses or unrecognized/incomplete responses remain unknown or invalid; never fill a draft with synthesized values. Omission interpretation is isolated in the API adapter and covered by compatibility tests.

## Script surface

The script checks `location.origin` for exact HTTPS production origin and parses only `/projects/{id}/{level}/edit` or `/en/projects/{id}/{level}/edit` (optional trailing slash). Ignore query/fragment for page identity. Other locale paths fail safely with instructions to open the supplied English edit URL. Check expected positive project ID and exact selected section before querying/mutating controls. This is an artifact guard, not a browser-control feature.

Status controls are radios named `project[{canonical_id}_status]` with exact canonical status values. Justifications are textareas named `project[{canonical_id}_justification]`. Metadata `name`, `license`, and `implementation_languages` use text inputs; `description` uses a textarea. Preflight every intended control for presence, expected element type, correct radio value, enabled/editable state, and unambiguous matching. Any preflight failure aborts all initial mutations and returns missing/invalid control names. All six levels require fixtures for these controls; an upstream mismatch blocks that gate rather than silently dropping metadata support.

Only after successful preflight, assign `.checked` or `.value` and dispatch bubbling input/change events. Return `{outcome: "filled"|"preflight_failed"|"runtime_failed", filled_fields: string[], missing_fields: string[], failed_field: string|null, message: string}`. Direct assignment/dispatch failures can leave already filled controls changed; catch these and report partial completion honestly. Exceptions thrown by page event listeners generally do not propagate through dispatchEvent and remain browser-reported; a filled report does not prove every downstream page handler succeeded. The artifact never fetches, navigates, submits, or saves. Serialize answer data as JSON and never use eval, innerHTML, or executable string interpolation. Suggested filename is `bestpractices-{project_id}-{level}.js`.

The plugin script builder lacks these guards/preflight checks, skips justification-only input, and omits metadata. Adapt concepts, not its behavior wholesale. Do not import its batching, selectors, registry, synchronization, or cross-process locks.

### M2 request serialization clarification

Route/query examples above describe parameter meaning; their textual order is schematic. Actual collection requests sort keys (`page` before `q`/`url`) and percent-encode spaces as `%20`, matching `ProjectsController#set_valid_query_url` and the pinned Addressable 2.9.2 `query_values=` implementation. This avoids canonicalization redirects without enabling redirect following. The synthetic [API fixture provenance](../../../tests/fixtures/api/provenance.json) records the exact source locations and an encoding example. These fixtures model the pinned source; an optional live observation does not establish the deployed revision.


### M2 correction: locale-independent JSON routes

The M0 baseline incorrectly prefixed public JSON reads with `/en`. M2's optional live probe observed the documented 301 redirect from `/en/projects/1.json` to `/projects/1.json`; source review confirmed this was a baseline mistake, not a new upstream requirement. Pinned [API quickstart](https://github.com/ossf/best-practices-badge/blob/868e1677339a3fdb48851b0c2ae8862c553115eb/docs/api.md#L28) recommends `/projects/1.json` and `/projects.json?url=URL`, and pinned [routes](https://github.com/ossf/best-practices-badge/blob/868e1677339a3fdb48851b0c2ae8862c553115eb/config/routes.rb#L90) define locale-independent JSON plus explicit redirects for localized record URLs. The route matrix above is corrected. The transport directly requests only those canonical JSON paths; it still rejects redirects and arbitrary paths/origins. English HTML edit paths for later artifact work are unchanged. This is a source-compatibility correction within the existing public-read scope.
